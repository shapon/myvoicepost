CONVENTIONS
-----------
  /api/v1/p/   Public  - no authentication required (guest access)
  /api/v1/a/   Auth    - requires JWT token in Authorization header
  /api/v1/wp/  Web-only public endpoints (not used by mobile)

AUTH HEADER (all /api/v1/a/ routes)
  Authorization: Bearer <jwt_token>

ERROR ENVELOPE (all endpoints)
  { "success": false, "error": "Human-readable message", "details": [...] }

SUCCESS/FAILURE always indicated by top-level "success": true|false

================================================================================
  SECTION 2 — TRANSCRIPTION
================================================================================

NOTE ON AUDIO FORMAT
  audio     : base64-encoded raw audio bytes
  mimeType  : "audio/mp4" (default) | "audio/m4a" | "audio/wav" | "audio/mpeg"
              "audio/webm" | "audio/ogg"

NOTE ON LANGUAGE CODES
  All language fields use BCP-47 codes: "en", "es", "fr", "de", "it", "pt",
  "nl", "ru", "zh", "ja", "ko", "ar", "hi", "tr", "pl", "vi", "th", "id"

--------------------------------------------------------------------------------
POST /api/v1/p/transcribe          [GUEST - auto-detect language]
POST /api/v1/a/transcribe          [AUTH  - auto-detect language]
  Purpose : Transcribe audio, auto-detect spoken language.
            Use when caller does NOT know the language in advance.
            Gemini is instructed: LANGUAGE: auto
  Auth    : p/ = none  |  a/ = JWT
  Request body:
    {
      "audio":           "<base64_string>",   // required
      "mimeType":        "audio/mp4",          // optional, default "audio/mp4"
      "durationSeconds": 40                    // optional, number
    }
  Guest limits: max 55 seconds, max 5 MB audio file
  Response 200:
    {
      "success":          true,
      "originalText":     "the full transcription here",
      "detectedLanguage": "en"                 // BCP-47, present if detected
    }
  Error 400: Audio too long / too large / no speech detected
  Notes:
    - Uses transcribeAudioAuto() in gemini.ts - independent prompt
    - Do NOT confuse with /transcribe_l which requires explicit language
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
POST /api/v1/p/transcribe_l        [GUEST - language-specific]
POST /api/v1/a/transcribe_l        [AUTH  - language-specific]
  Purpose : Transcribe audio in a specific language only.
            Caller MUST provide the language code.
            Gemini is instructed: EXPECTED LANGUAGE: <lang>
            Words spoken in other languages are IGNORED.
  Auth    : p/ = none  |  a/ = JWT
  Request body:
    {
      "audio":           "<base64_string>",   // required
      "mimeType":        "audio/mp4",          // optional, default "audio/mp4"
      "language":        "en",                 // REQUIRED - BCP-47 code
      "durationSeconds": 40                    // optional, number
    }
  Guest limits: max 55 seconds, max 5 MB audio file
  Response 200:
    {
      "success":      true,
      "originalText": "the full transcription here",
      "language":     "en"                     // echoes requested language
    }
  Error 400: Audio too long / too large / no speech detected
  Notes:
    - Uses transcribeAudio() in gemini.ts - independent prompt (separate from /transcribe)
    - detectedLanguage is NOT returned (language was caller-specified)
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
POST /api/v1/a/mp/transcribe       [AUTH - multipart auto-detect, 1-6 snippets]
  Purpose : Upload 1-6 pre-recorded 10-second audio snippets as multipart FormData.
            Transcribes each snippet sequentially (auto-detect language) and returns
            the concatenated text in chronological order.
            Used by the mobile Snippet Recorder architecture.
  Auth    : JWT (Bearer)
  Request : multipart/form-data
    snippet_0  ... snippet_N  : audio files (m4a/mp4), max 6
    mimeType   : string (optional, default "audio/mp4")
  Response 200:
    {
      "success":      true,
      "originalText": "full concatenated transcription"
    }
  Error 400: No files, or no speech detected in any snippet
  Notes:
    - Files are sorted by fieldname (snippet_0 < snippet_1 …) before processing
    - Each snippet is transcribed individually via transcribeAudioAuto()
    - Empty snippets are skipped, non-empty are joined with a space
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
POST /api/v1/a/mp/transcribe_l     [AUTH - multipart language-specific, 1-6 snippets]
  Purpose : Same as /api/v1/a/mp/transcribe but language-specific.
            Transcribes each snippet in the given language, ignoring other languages.
  Auth    : JWT (Bearer)
  Request : multipart/form-data
    snippet_0  ... snippet_N  : audio files (m4a/mp4), max 6
    language   : string (REQUIRED - BCP-47 code e.g. "en", "fr")
    mimeType   : string (optional, default "audio/mp4")
  Response 200:
    {
      "success":      true,
      "originalText": "full concatenated transcription",
      "language":     "en"
    }
  Error 400: No files, missing language, or no speech detected
--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
POST /api/v1/a/transcribe-url
  Purpose : Download audio from a URL and transcribe it
  Auth    : JWT
  Request body:
    {
      "url":      "https://example.com/audio.mp3",  // required
      "language": "en"                               // optional, default "en"
    }
  Response 200:

--------------------------------------------------------------------------------
POST /api/v1/a/transcribe-file

  Content-Type: multipart/form-data
  Form fields:

  SECTION 3 — POLISH (TEXT QUALITY IMPROVEMENT)

--------------------------------------------------------------------------------
POST /api/v1/p/polish              [GUEST]
POST /api/v1/a/polish              [AUTH]
  Purpose : Polish / improve raw transcription text.
            p/ uses field "text"; a/ uses field "originalText"
  Auth    : p/ = none  |  a/ = JWT

  GUEST request body  (/api/v1/p/polish):
    {
      "text":         "raw transcribed text",   // required
      "language":     "en",                      // optional, default "en"
      "outputFormat": "professional",            // optional, default "professional"
                                                 //   "professional"|"casual"|"formal"|"friendly"
      "outputType":   "message"                  // optional, default "message"
                                                 //   "message"|"note"|"email"|"post"|"journal"
    }
  GUEST response 200:
    {
      "success":      true,
      "originalText": "raw transcribed text",
      "polishedText": "improved version",
      "language":     "en",
      "outputFormat": "professional",
      "outputType":   "message"
    }

  AUTH request body  (/api/v1/a/polish):
    {
      "originalText": "raw transcribed text",   // required  (note: field name differs from guest)
      "language":     "en",                      // optional, default "en"
      "outputFormat": "paragraph",               // optional, default "paragraph"
      "outputType":   "general"                  // optional, default "general"
    }
  AUTH response 200:
    {
      "success":      true,
      "originalText": "raw transcribed text",
      "polishedText": "improved version",
      "language":     "en",
      "outputFormat": "paragraph",
      "outputType":   "general"
    }

  IMPORTANT: Field name difference:
    Guest (/p/)  uses "text"         as request field
    Auth  (/a/)  uses "originalText" as request field

================================================================================
  QUICK REFERENCE — ENDPOINT ROUTING DECISION
================================================================================

  User is a GUEST (not logged in)?
    Transcription (auto):      POST /api/v1/p/transcribe
    Transcription (language):  POST /api/v1/p/transcribe_l
    Polish text:               POST /api/v1/p/polish           (body field: "text")
    Translate text:            POST /api/v1/p/translate        (body field: "text")
    Process URL:               POST /api/v1/p/process-url

  User is LOGGED IN (has JWT)?
    Transcription (auto):      POST /api/v1/a/transcribe
    Transcription (language):  POST /api/v1/a/transcribe_l
    Polish text:               POST /api/v1/a/polish           (body field: "originalText")
    Translate text:            POST /api/v1/a/translate        (body field: "originalText")
    Process URL:               POST /api/v1/a/process-url
    Save result:               POST /api/v1/a/saved-texts
    View saved:                GET  /api/v1/a/saved-texts
    My account:                GET  /api/v1/a/auth/me
    Subscription:              GET  /api/v1/a/subscription

  CRITICAL FIELD NAME DIFFERENCE (common bug source):
    /api/v1/p/polish    and  /api/v1/p/translate  ->  "text"
    /api/v1/a/polish    and  /api/v1/a/translate  ->  "originalText"
